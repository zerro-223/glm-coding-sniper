# GLM Coding Plan 抢购助手 — 设计文档

> 日期: 2026-06-17  
> 类型: 油猴脚本 (Tampermonkey)  
> 目标站点: `open.bigmodel.cn` / `www.bigmodel.cn/glm-coding`

---

## 1. 概述

### 1.1 目标

在智谱 AI 开放平台的 GLM Coding Plan 套餐页面上，实现高度自动化的抢购辅助。用户只需提前打开页面并完成扫码支付，其余流程由脚本自动处理。

### 1.2 核心原理

在底层拦截并篡改服务器返回的数据流。通过劫持浏览器的 `JSON.parse` 和网络请求接口 (`fetch`/`XHR`)，将响应数据中的 `isSoldOut` 或 `disabled` 等属性强制改为 `false`，让页面原生激活支付按钮，避开前端逻辑限制。

### 1.3 抢购场景

- 每日限量发售，通常在上午 **10:00** 开抢
- 页面在开售前按钮处于 disabled 状态，数据标注 `isSoldOut: true`
- 开售瞬间服务器放开库存，先到先得
- 10:00 未抢到需持续重试至 10:05（未付款释放名额）

## 3. 模块详细设计

### 3.1 控制面板

在页面右下角注入 Shadow DOM UI，样式隔离，页面 JS 不可访问。

**面板布局:**
```
┌─────────────────────────────────┐
│  🔥 GLM 抢购助手 v1.0           │
│─────────────────────────────────│
│  目标套餐:  [Lite ▼]           │
│  付费周期:  [连续包月 ▼]       │
│  开抢时间:  [09:59:58]         │
│  提前触发:  [200ms]            │
│─────────────────────────────────│
│  并发数:    [5] 路              │
│  最大重试:  [2000] 次           │
│  极速爆发:  [20] 次零延迟       │
│─────────────────────────────────│
│  状态: 🟢 等待开抢...           │
│  日志:  [最近5条滚动显示]       │
│─────────────────────────────────│
│  [ 开始监控 ]  [ 立即抢购 ]     │
│  [ 重置 ]     [ 隐藏面板 ]     │
│─────────────────────────────────│
│  ⚡ 快捷键: Alt+S 开始  Alt+X 停止│
└─────────────────────────────────┘
```

**功能特性:**
- 面板可拖拽、可最小化（收起为浮动小图标）
- 目标套餐下拉框自动读取页面上的套餐列表
- 开抢时间支持手动输入，默认 09:59:58（提前 2 秒触发）
- 状态指示灯: 🟢等待 → 🟡抢购中 → 🟢成功/🔴失败
- 成功时播放提示音 + 浏览器通知
- 所有配置通过 `localStorage` 持久化

### 3.2 请求拦截器

**注入时机:** `@run-at document-start`（在页面脚本执行前注入）

#### 3.2.1 JSON.parse 劫持

```
页面原始响应:  { "isSoldOut": true, "disabled": true, ... }
        ↓
劫持修改后:   { "isSoldOut": false, "disabled": false, ... }
        ↓
Vue/React 拿到修改后的数据 → 按钮自然变为可点击
```

递归遍历 JSON 对象的所有层级，将以下属性强制改为 false:
- `isSoldOut`
- `soldOut`
- `disabled`（仅当对象同时包含 `price` 或 `productId` 等商品标识时）
- `isServerBusy`

#### 3.2.2 fetch/XHR 劫持

```
用户点击购买
    ↓
拦截 fetch → 捕获请求参数 (url, body, headers)
    ↓
如果并发引擎运行中 → 参数交给引擎接管
    ↓
否则 → 放行原始请求
```

同时劫持响应流，对返回的 JSON 做与 3.2.1 相同的数据造假处理。

#### 3.2.3 MutationObserver 兜底

监听 DOM 变化，当检测到按钮出现 `disabled` 属性或 `is-disabled` class 时自动移除。

### 3.3 并发重试引擎

#### 3.3.1 三阶段自适应间隔

| 阶段 | 重试次数 | 间隔 | 策略 |
|------|----------|------|------|
| 极速爆发 | 前 20 次 | 零延迟 | 抢占开售瞬间 |
| 快速重试 | 21~100 次 | ~30ms + ±30% 抖动 | 持续施压 |
| 稳定重试 | 101 次+ | ~100ms + ±30% 抖动 | 避免 WAF |

#### 3.3.2 双轨并发模式

| 模式 | 并发数 | 持续时间 | 策略 |
|------|--------|----------|------|
| 极速 | 10 路 | 前 5 秒 | 全力冲刺 |
| 普通 | 5 路 | 持续 | 细水长流 |

#### 3.3.3 请求流水线

```
preview 请求 (多路并发)
    ↓
Promise.race — 任一成功即取消其余
    ↓
拿到 bizId → 立即 check 校验
    ↓
├─ OK → 锁单成功 → 触发支付
└─ EXPIRE → 立即重试 preview
```

#### 3.3.4 黄金捡漏期

10:00 没抢到不立即停止。在 **10:05 之前**持续以普通模式重试，捡漏因未付款释放的名额。

### 3.4 反检测

| 措施 | 实现 |
|------|------|
| 请求指纹随机化 | 每次请求随机生成 `X-Request-Id`、`X-Timestamp`(±2s)、`Accept-Language` |
| toString 伪装 | 劫持后 `fetch`/`XHR.send` 的 `toString()` 返回 `[native code]` |
| 频率抖动 | 重试间隔加入 ±30% 随机因子 |
| Shadow DOM | 面板使用 `mode: 'closed'`，页面 JS 无法读取 |

### 3.5 定时器

- 使用 `requestAnimationFrame` + `performance.now`，精度 ±2ms
- 服务器时间校准: 发送 HEAD 请求 → 读取 `Date` 响应头 → 计算本地与服务器偏差 → 按服务器时间触发
- 默认提前 200ms 触发（可配置），补偿网络延迟

### 3.6 支付弹窗恢复

抢到订单但弹窗未弹出时，按以下顺序递进恢复：

| 层级 | 策略 | 实现 |
|------|------|------|
| 1 | 清除遮罩 | 移除 `.el-dialog__wrapper` / `.v-modal` |
| 2 | 重新触发 | 用缓存的响应数据重新点击购买按钮 |
| 3 | 直接获取链接 | 用 bizId 请求支付链接 → `window.open()` |
| 4 | Vue 组件树兜底 | 定位 Vue 实例 → 直接设置 `payDialogVisible = true` |

### 3.7 验证码处理

由于不确定是否存在验证码，采用两手准备:
- 脚本持续监控页面是否出现验证码弹窗
- 若检测到验证码 → 弹窗高亮提醒用户手动完成 → 验证通过后自动继续流程
- 预留 OCR 接口扩展点，后续可对接本地 OCR 服务

## 7. 风险与限制

| 风险 | 应对 |
|------|------|
| 页面改版导致选择器失效 | 面板提供手动刷新选择器按钮 |
| API 端点变更 | 劫持层自动捕获最新端点，不硬编码 URL |
| WAF 触发 405/403 | 自适应降频 + 随机抖动 |
| 后端严格校验导致绕过失败 | 仅能解除前端限制，无法保证 100% 成功 |
| 浏览器标签页后台被节流 | 提示用户保持标签页前台 |
